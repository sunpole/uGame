# UGD-0013 — Interaction UI, награды и динамические Event Spots

Дата: 2026-10-06
Тип: system
Статус: accepted
Flags: needs-test, needs-calculation
Теги: gameplay, events, interaction, rewards, resources, world, randomness, persistence, ui

## Контекст

После UGD-0010–UGD-0012 принято перейти к playable-прототипу, где дополнительные события появляются на специальных Event Spots, живут ограниченное время и открывают разные типы взаимодействий.

## Принятое направление

Рабочая цепочка:

```text
Event Spot
→ случайный Interactable
→ Event
→ Interaction UI / Dialogue / Reward
→ результат
→ Game State / Resources / будущие модули
```

Interaction UI — переиспользуемая оболочка для окон взаимодействия. Разговоры остаются в DialogueSystem, а Reward Choice, информационное окно портала и будущие Shop/Training/Process/Travel могут использовать общую оболочку.

## RewardGenerator

Генерация награды отделена от конкретного объекта. Сначала определяется количество вариантов, затем допустимое число выборов, затем для каждого варианта отдельно бросается rarity и содержимое. Уже созданное предложение сохраняется в Game State, поэтому F5 не должен давать бесплатный reroll.

Стандартный rarity-профиль прототипа: normal 80%, rare 15%, magic 3.5%, unique 1.5%. Это тестовый баланс, не финальные вероятности.

## Resource Event

Ресурсное событие генерирует 2–3 варианта. Качество каждого варианта рассчитывается отдельно. В текущем прототипе игрок выбирает один вариант.

## Chest Event

Для сундука используются два независимых rarity-roll: сколько закрытых сундуков показать и сколько разрешить забрать. Таблица текущего прототипа: normal=1, rare=2, magic=3, unique=5. Каждый сундук заранее получает отдельное скрытое содержимое и раскрывается только после выбора.

Ранее в примере одновременно фигурировали максимум 5 сундуков и таблица с максимумом 4. Для прототипа принято unique=5, чтобы максимум действительно был пять.

## Каталог ресурсов

До ЛОРа используются условные ресурсы и относительная стоимость в Камне: Камень=1, Дерево=10, Вода=100, Внимание=5000. Внимание остаётся account-bound концепцией.

Для текущего preset rarity временно связан с типом ресурса: normal→Камень, rare→Дерево, magic→Вода, unique→Внимание. Архитектурно ResourceType и Rarity остаются разными сущностями, чтобы позже не закреплять эту связь навсегда.

Черновой бюджет награды в эквиваленте Камня: normal 1–10, rare 10–20, magic 20–100, unique 100–250. Из-за стоимости Внимания=5000 текущий min=1 для unique может превышать номинальный бюджет; это известное несогласованное место тестовых чисел и требует будущей балансировки.

## Dynamic Event Spots

Каждая текущая зона получает 5 возможных точек. Качество зоны определяет число одновременно активных Event Slots: Q1=1, Q2=2, Q3=3, Q4=5.

Качество зоны бросается по той же тестовой rarity-схеме: Q1 80%, Q2 15%, Q3 3.5%, Q4 1.5%. Большинство зон поэтому большую часть времени имеют один дополнительный Event.

Каждый дополнительный Event живёт 30 минут и показывает обратный таймер. После окончания слот получает новое событие и может сменить точку среди пяти. Если награда уже забрана, объект исчезает, но слот ждёт своего следующего цикла.

Качество каждой зоны пересчитывается независимо. Тестовые интервалы: Q1 150–180 мин, Q2 120–160, Q3 75–120, Q4 60–90. Обычные зоны стабильнее, редкие меняются быстрее. Таймеры зон не синхронизированы.

Первый набор динамических событий: Resource Event, Chest Event, Event Portal. Event Portal пока только открывает информационное окно; позже он может вести в отдельные временные Event Zones, например подземелья или испытания.

Текущие тестовые веса типов события: resource 60%, chest 30%, event-portal 10%. Это QA-настройка, а не утверждённый баланс.

## Persistence

Сохраняются качество каждой зоны, время следующего reroll, текущие Event Slots, время окончания Event, consumed state, pending reward offer и уже сделанные выборы. Это защищает систему от бесплатного reroll через переходы между зонами или перезагрузку страницы.

## QA

DEV-коды прототипа: 8201 — пересоздать Event текущей зоны без смены её качества; 8202 — заново бросить качество текущей зоны и пересоздать слоты; 8211 / 8212 / 8213 / 8214 — принудительно поставить Q1 / Q2 / Q3 / Q4 для быстрой проверки 1 / 2 / 3 / 5 активных слотов; 8299 — краткий статус Dynamic Event системы.

## Реализация

Первый playable-прототип этой записи — v0.0.32. Конкретные вероятности, интервалы и цены остаются прототипными и могут меняться без пересмотра самой архитектуры.
