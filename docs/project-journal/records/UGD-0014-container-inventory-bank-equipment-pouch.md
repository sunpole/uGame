# UGD-0014 — Контейнеры: рюкзак, банк, экипировка и ресурсный пояс

Дата: 2026-10-06  
Тип: system  
Статус: accepted  
Flags: needs-test, needs-calculation  
Теги: inventory, containers, bank, equipment, resources, weight, stacking, progression, ui, persistence

## Контекст

Инвентарь uGame не должен быть одним бесконечным счётчиком предметов. Хранение становится отдельным игровым слоем с ячейками, stack limit, весом и будущей прокачкой.

Чтобы не создавать независимые BackpackSystem, BankSystem, EquipmentSystem и ResourcePouchSystem, принято использовать один базовый ContainerSystem с разными конфигурациями и правилами доступа.

## Базовая модель

```text
Item / Resource
├─ id
├─ type / tags
├─ weightPerUnit
├─ stackLimit
├─ baseValue (для ресурсов)
└─ equipSlot / storageMode при необходимости

Container
├─ kind
├─ slotCount / named slots
├─ maxWeight
├─ allowedTags / allowedItemIds
├─ access
└─ modifiers
```

Одинаковые предметы могут складываться в stack до лимита предмета/контейнера. Один stack занимает одну ячейку.

Пример: при stack limit 100 количество 250 одного предмета занимает 3 ячейки: 100 + 100 + 50.

## Рюкзак

Рюкзак всегда переносится с персонажем и доступен из интерфейса в любой локации.

Текущие тестовые значения прототипа:

- 12 ячеек;
- 30 кг;
- обычные предметы и физические ресурсы могут занимать ячейки;
- ограничения должны в будущем изменяться через навыки/профессии.

## Банк

Банк — локальная инфраструктура города, а не постоянно доступная глобальная вкладка.

В прототипе объект Банка расположен на Перекрёстке как временной городской/hub-сервис. Взаимодействие с объектом открывает Bank container и разрешает перенос между переносными контейнерами и Банком.

Текущие тестовые параметры:

- 60 ячеек;
- без весового ограничения;
- доступ только через объект Банка.

Позже размеры/функции Банка также могут развиваться через отдельные навыки/профессии/инфраструктурный прогресс.

## Экипировка

Equipment — специализированный контейнер с именованными слотами:

- helmet;
- chest;
- pants;
- boots;
- gloves;
- ring1;
- ring2;
- amulet;
- cloak;
- belt.

Предмет можно экипировать только в соответствующий слот. В прототипе DEV-код добавляет тестовый шлем и пояс для проверки механики.

Оружие сознательно пока не добавлено в фиксированный список: боевая система отложена и её требования ещё не определены.

## Ресурсный пояс / отдельное хранение ресурсов

Resource Pouch — переносной специализированный контейнер ресурсов, который позже может быть связан с поясом или другой экипировкой.

Стартовый прототип специально ограничен:

- 1 ячейка;
- 15 кг;
- разрешён только Камень.

Камень при получении сначала пытается попасть в Resource Pouch, затем — в рюкзак. Дерево и Вода пока занимают рюкзак. В будущем навыки смогут открывать дополнительные виды ресурсов, ячейки, вес и stack limit.

Это проверяет сам принцип отдельного ресурсного хранения без преждевременной реализации дерева профессий.

## Навыки / профессии

ContainerSystem уже хранит modifiers, которые позднее могут изменяться Skill/Profession-модулями:

- slotBonus;
- maxWeightBonusKg;
- stackLimitBonus;
- дополнительные allowedItemIds.

Таким образом прокачка не должна переписывать контейнер — она меняет его параметры.

## Ресурсы и вес

До появления финального ЛОРа используются тестовые параметры:

| Resource | Base value | Weight / unit | Stack limit | Storage |
| --- | ---: | ---: | ---: | --- |
| Камень | 1 | 1 кг | 100 | physical |
| Дерево | 10 | 0.5 кг | 100 | physical |
| Вода | 100 | 0.1 кг | 100 | physical |
| Внимание | 5000 | 0 | 999999 | account / intangible |

Тенденция «дороже → легче» пока является рабочим примером, а не универсальным законом экономики.

Внимание нематериально, поэтому не занимает ячейки и не создаёт вес.

## Связь с Reward/Event

```text
Dynamic Event / Quest / Chest
        ↓
Reward
        ↓
ContainerSystem
   ├─ Resource Pouch
   ├─ Backpack
   └─ account resource
```

Если физическая награда не помещается по ячейкам/весу, ограниченный Reward Choice не должен считаться выбранным: предложение остаётся доступным, пока игрок не освободит место.

## Persistence и миграция

Состояние контейнеров сохраняется в общем Game State:

- все grid slots;
- equipment slots;
- modifiers;
- Bank;
- Resource Pouch.

Старый flat inventory автоматически мигрирует в Backpack; переполнение миграции отправляется в Bank. Старые физические Stone/Wood/Water counters также мигрируют в переносные контейнеры, а остаток — в Bank. Это только правило миграции старого сейва, не обычная выдача наград.

## Что ещё не решено

- финальные размеры и весовые лимиты;
- точная формула развития инвентаря;
- влияние экипированной брони на общий переносимый вес;
- привязка Resource Pouch именно к Belt как обязательное правило;
- количество ресурсных типов/слотов на высоких уровнях;
- отдельные складские/гильдейские контейнеры;
- сортировка, drag-and-drop, разделение stack;
- server-authoritative storage для будущей online-версии.
