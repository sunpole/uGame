# Настройка проекта uGame в ChatGPT

Обновлено: 2026-10-09. Это руководство для владельца проекта. Оно **не исправляет** баг интерфейса ChatGPT, при котором уже видимый ответ может исчезнуть. Цель — снизить зависимость от отображения чата и сохранять результаты работы в GitHub.

## 1. Где находятся инструкции ChatGPT

Откройте ChatGPT → список **Проекты** → **uGame** → меню **•••** → **Настройки проекта** → **Инструкции проекта**. При наличии ранее введённого текста сохраните его полезные части и добавьте новый блок, не стирая важные правила.

Инструкции проекта относятся к проекту uGame в ChatGPT. Файл `AGENTS.md` в GitHub — **отдельные** инструкции для агентов разработки; его изменение само по себе не обновляет настройки ChatGPT.

## 2. Текст, который можно скопировать в «Инструкции проекта»

```text
Работаем над игрой uGame: https://github.com/sunpole/uGame .
Отвечай на русском, кратко и понятно. Предпочитай маленькие последовательные шаги. Сначала выясняй фактическое состояние main, последнего релиза и документации AGENTS.md, если доступен GitHub.

КРИТИЧНО: после долгой разработки уже отображённые ответы ChatGPT у пользователя иногда исчезают. Ты не управляешь интерфейсом и не можешь гарантировать закрепление ответа. Поэтому не храни важные результаты только в чате.

После существенной задачи:
1) Сохрани реальный результат в GitHub: коммиты, PR, docs/releases для релиза либо отдельный work-report для крупной работы без релиза.
2) Дай короткий, самодостаточный ОКОНЧАТЕЛЬНЫЙ ОТЧЁТ обычным Markdown. Не полагайся только на цветные панели, карточки и виджеты.
3) В отчёте укажи: фактический статус, что изменено, результаты тестов, PR/коммит/релиз, как мне проверить, что осталось незавершённым.
4) Не называй задачу выполненной, если PR не объединён, релиз не опубликован либо браузерный QA не пройден. Точно отличай CI от ручного тестирования Windows.
5) При длительной работе сообщай короткие проверенные контрольные итоги, чтобы было ясно, какой этап уже завершён.
6) Если я пишу «ответ исчез», «повтори отчёт» или «где результат», восстанови отчёт из GitHub без просьбы повторно описывать задачу.

Не меняй баланс игры, сохранения или принятую концепцию без задания. Для релизов сохраняй предыдущую точку отката. Для изменений Pre-flight, Phaser, загрузки и UI используй настоящий Chromium desktop/mobile smoke-test. Игровые решения и гипотезы фиксируй в Project Journal с правильным статусом.

Мне важны одновременно аккуратная подача, реальная проверка, короткое объяснение и надёжное сохранение результата.
```

## 3. Источники проекта

При желании добавьте через «Добавить источник» копию `AGENTS.md`, `README.md` и `VERSION.md`. Также можно ссылаться на живой репозиторий и просить ассистента проверять его с подключённым GitHub.

**Важно:** загруженная копия `AGENTS.md` не обязана автоматически синхронизироваться при новых коммитах. Содержимое в GitHub и проектные источники нужно сверять. Не загружайте токены, реальные пользовательские сохранения и секреты.

## 4. Организация бесед

- Один разговор для текущей серии патчей; отдельный — для крупного игрового шторма или исследования баланса. Контрольные результаты сохраняются не только в чатах, но и в GitHub.
- После большого цикла удобно написать: «Подведи короткий итог в обычном Markdown; проверь и укажи ссылки на коммиты, PR, релиз и отчёт в репозитории».
- Если UI снова скрыл уже показанное сообщение, откройте чат повторно/перезагрузите страницу; при повторяемой ошибке сообщите в поддержку ChatGPT, приложив скриншот и время. **Ни AGENTS.md, ни эти настройки не могут гарантировать, что ошибка отображения исчезнет.**

## 5. Память проекта

В настройках проекта при наличии выбора памяти можно использовать режим **«Только память проекта»**, чтобы контекст других проектов меньше смешивался с uGame. Это влияет на контекст, **не на исчезновение сообщений**. Не переключайте память только в надежде исправить отображение ответов.

## 6. Источники истины

- `AGENTS.md` — правила для ассистентов/кодовых агентов.
- `docs/releases/` — история версий и проверок релизов.
- `docs/project-journal/` — решения, гипотезы и история концепции.
- `docs/work-reports/` — только значимые задания без версии, если требуется долговременный технический отчёт.
- `main`, подтверждённые PR и GitHub Actions — фактические изменения и результаты CI.
