# uGame — Character Balance Lab: GLR link correctness, trace and extended pinning

**Дата:** 2026-10-11. **Статус:** PR [#61](https://github.com/sunpole/uGame/pull/61) объединён в `main`; код в [d9cb48c](https://github.com/sunpole/uGame/commit/d9cb48c300a198509715e90ec66c5875de661aba).

**Версия игры:** v0.2.57 (без нового релиза); прежняя точка отката [v0.2.57](https://github.com/sunpole/uGame/releases/tag/v0.2.57) и предшествующая [v0.2.56](https://github.com/sunpole/uGame/releases/tag/v0.2.56) сохранены. Изменения только в DEV Character Balance Lab, тестах, CSS и безопасном JSON snapshot; **не менялись Phaser, SaveSystem, действующий StepSystem, формулы/баланс живой игры, значения исходного кандидатного JSON и Journal decisions**.

## Исходная проблема и установленная причина

На скриншотах пользователь показывает, что GLR (ГЛР), добавленный в конструкторе как `increased` или `more`, увеличивает значение ГЛР, но **не** распространяется на производные регенерации. Установленная причина: в расчётном ядре влияние ГЛР на `hps`, `rps`, `pps`, `jps`, `rgs` применялось **до** обработки `increased/more` самого ГЛР.

## Что изменено

1. Пересобран порядок **кандидатного** расчёта: все flat → суммарные по показателю increased → независимые последовательные more → кап ГЛР → зависимые бонусы столицы (в том числе РП→РПС у Темпа) → общий ГЛР к пяти регенерациям → остальные верхние caps. Значения по старым стандартным формулам (без добавленных модификаторов) и исторические обозначения трасс сохранены.
2. ГЛР считает все пять регенераций от **конечного отображаемого значения** (включая три вида модификаторов и верхний предел), с явным этапом «ГЛР: ...» в трассе. Изменения ГЛР теперь влияют на ХПС, РПС, ППС, ЖПС и РГШ.
3. Закреплённая панель больше не ограничена `37vh`: растёт **до почти всей высоты окна**; при большом числе строк прокручивается **внутри** панели, без перекрытия за пределами viewport.
4. В шапке отдельное **«+ Добавить»** с выбором всех 24 производных и 9 исходных/информационных полей: ЗРЛ, ВЫН, ЛОВ, ИНТ, ОТВ, столица, тип ресурса (СИЛ/КОН/ТЕМП/ВДОХ), состояние Желания, свободные очки.
5. Ячейки закреплённой панели стали интерактивными: **наведение/фокус показывает всплывающую расшифровку**, клик открывает прокручиваемый диалог со всеми источниками, промежуточными значениями, increased, more, ГЛР и cap, если был. Например **УСТ=1001** раскладывается на **+1000 при ЖП>0** и **+1 за ЗРЛ 1** (нулевая база). Пользователь может найти, где поправить коэффициент.
6. Разрешено экспортировать/импортировать новые выбранные input pins через исходный защищённый JSON snapshot с проверкой SHA-256. Старые файлы и прочие значения неизменны, исходный snapshot format version не повышался.

## Как проверить владельцу

1. Обновить локальный main через Updater → 1, запустить Quick Run → открыть `http://127.0.0.1:5173/character-lab/` или GitHub Pages после публикации.
2. На закреплённой панели справа выбрать `ОТВ` → `+ Добавить`; затем `ВЫН`, `ЛОВ`, `ИНТ`, `ГЛР`, `УСТ`, тип ресурса. Добавить больше семи строк: панель растёт до низа окна, потом начинает прокручиваться.
3. Навести мышь на `УСТ 1001` в профиле ЗРЛ 1 → источник `ЖП > 0 +1000`, уровень `+1`; щёлкнуть и увидеть полный список. Нажать на ОТВ и увидеть его источник (карточка профиля).
4. В редакторе `За 1 ЗРЛ` изменить ГЛР через `⋯ Изменить` или `+ Добавить` → `increased` или `more`. Закрепить ГЛР, ХПС, РПС, ППС, ЖПС и РГШ и убедиться, что увеличение ГЛР меняет все пять скоростей. Кнопка `Вернуть стандарт` возвращает исходные коэффициенты.
5. Сохранить свои эксперименты в JSON (включая новые закрепления) для обсуждения; игровое сохранение не затрагивается.

## Что осталось открытым

- Проектный баланс (формулы ОТВ, стартовые пассивы, урон, combat, PvP, НР и ограничения) **не утверждён и не реализован в gameplay**; «126/126» не доказывает его.
- Пользовательская ручная QA на Windows; специальные отрицательные или экстремальные проценты остаются экспериментальными и требуют отдельных игровых решений.
- При дополнительной разработке интерфейса можно сделать изменяемую визуальную высоту панели, но в текущем запросе достаточно роста до viewport.
