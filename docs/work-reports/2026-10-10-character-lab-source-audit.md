## Что не охвачено из UGD-0038 №1–93

- Правила оплаты умения Желанием, состояния ресурсов, начало/остановка ЖПС и реальная регенерация только в открытой игровой сессии (включая неактивную вкладку/AFK, без накопления после закрытия).
- Граф пассивных узлов с четырьмя бесплатными старто́выми узлами, связанностью веток, временными очками нескольких предметов, отключением и восстановлением зависимых узлов.
- Опыт ЗРП, границы четырёх фаз, 0 опыта при разнице уровней монстр/игрок больше 9, награды чемпионов и боссов, отдельные множители сложности, распределение между 1–12 участниками, онлайн/живые/поблизости/группа с начала боя и проверка событий убийств.
- Потеря опыта при PvE/PvP-смерти, перенос излишка ЗРП с пересчётом штрафа при новом уровне, антигринд множители.
- Реальное использование новых статов в игре и контракт с существующей экономикой Шагов/инвентаря.

## Конкретные риски и источники разночтений

1. Пример HP=100 в baseline делает все начальные профили жизнеспособными математически, но сам по себе не доказывает жизнеспособность. При HP=0 и без ещё не заданного стартового пассива у допустимых стартов столиц Концентрации и Темпа может быть ВЫН=0, то есть ХП=0. Нужно тестировать 21 вариант по настоящим источникам после определения узлов.
2. ЖП>0 / ЖП=0 сегодня переключается вручную даже без смоделированного текущего количества Желания и статуса полного РП.
3. В Lab ОТВ=600 с ЗРЛ3 — сценарий. Принятый сюжет: шесть стартовых квестов по +100 примерно к ЗРЛ3; при изначальном рейтинге 1 получится 601, что всё равно шесть полных сотен. Не делать из сценария автоматическое повышение ОТВ за уровень.
4. ШАГ в Lab имеет исходную базу 0, а действующая игра имеет собственную экономику Шагов (начальный запас 10 000, лимит 100 000 000, +5/сек в городе). Новую систему нельзя подключать до согласования единиц, баз и источников.
5. Отрицательные значения ОТВ пока используют усечение к нулю как временную интерпретацию. Строгие правила штрафов не приняты.
6. Свободное распределение очков в defaultProfile делается поровну только ради примера. Это не автоматическое игровое распределение, в игре игрок выбирает сам.
7. Статус существующей лаборатории — кандидат/расчётный эксперимент, не принятый баланс. Существующие 94/94 Node и Chromium desktop/mobile тесты v0.2.55 не доказывают полноту механик.

## Требования к будущему улучшению (предложение, не утверждённая реализация)

### A. Полный реестр и навигация

Машинный реестр не только для всех 24 выходных метрик, но и для 5 базовых характеристик, 4 ресурсов происхождения, условных/временных состояний, ЗРП, боевых, группово-опытных и пассивных правил. Для каждого элемента: stable id; сокращение; полное название; единицы; что делает; на что влияет; источники; зависимости; способ вычисления и ограничения; статус accepted/candidate/missing; конкретные ссылки на строки оригинала/решения UGD; места реализации; примеры. Отдельно показывать незакрытые правила без выдуманных коэффициентов.

### B. Закреплённая панель сравнения

В каждой строке результата кнопка 📌. Закрепить любые показатели для выбранных 1–4 профилей в sticky-панели сверху, обновлять сразу после изменений, высоту ограничивать с внутренней прокруткой, особенно на мобильном экране. Дать кликабельную формулу/источники для каждой строки.

### C. Переносимый экспорт/импорт

Версионированный JSON snapshot со schemaVersion, reference Git SHA, кандидатными коэффициентами и отдельными правками, 1–4 профилями, списком закреплённых метрик, рассчитанными значениями и формулами/trace, warnings, статусами утверждения, timestamp и контрольной суммой. При импорте валидация схемы и показ разницы до применения только в sandbox. Такой файл можно передавать разработчику/ChatGPT без пересказа.

### D. Безопасное будущее применение к игре

Изолировать режимы:
1. Лаборатория/черновик — любое редактирование без сохранений игрока.
2. Тестовый мир — применение к синтетическому персонажу без изменения реальных сейвов.
3. Утверждённый игровой баланс — отдельный согласованный конфиг, PR/review, проверки и опубликованный релиз с точкой отката.

GitHub Pages — статический хостинг, который не может сам авторизованно коммитить изменения напрямую в репозиторий. Для реальной серверной админки понадобится отдельный защищённый процесс публикации, а не простой browser-local editor.
