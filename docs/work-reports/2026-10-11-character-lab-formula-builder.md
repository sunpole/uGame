# uGame · Character Lab formula builder — конструктор зависимостей

Дата: 2026-10-11. **Итог: [PR #60](https://github.com/sunpole/uGame/pull/60) объединён в main, squash commit [88e9e7d](https://github.com/sunpole/uGame/commit/88e9e7dee00fa8c22ca5d2aa65683004c7cd156c). Проверка PR: CI PASS, 121/121 Node и реальные desktop/mobile Chromium PASS.**
Базовый main `c16e73e1fa9470ea063b5475c4be39beaa33835d`, последний QA-релиз [v0.2.57](https://github.com/sunpole/uGame/releases/tag/v0.2.57), резервный откат [v0.2.56](https://github.com/sunpole/uGame/releases/tag/v0.2.56).
Только **изолированная кандидатная** Character Balance Lab; реальный GameState, SaveSystem, StepSystem, NPC, классы, реальные значения экономики **не менялись**.

## Что реализовано

- Пользователь может добавить любой из **24** результирующих показателей в любую из **12 групп-источников**: 6 базовых/атрибутных (исходная база, ВЫН, ЛОВ, ИНТ, ЗРЛ, ОТВ), два состояния Желания и четыре столицы.
- Для одной характеристики внутри одной группы доступны одновременно **flat** (число единиц), **increased** (суммируемый процент) и **more** (отдельный умножающий процент).
- Каждая строка имеет числовое поле и кнопку **«Изменить»**, открывающую диалог замены характеристики/типа/значения или удаления. Каждая группа имеет **«+ Добавить характеристику»**; одинаковое сочетание группа+показатель+тип запрещено, разные типы одной характеристики допускаются.
- В основной панели: **«Вернуть стандарт»** (сбрасывает все кандидатные правки и исходные профили) и уже существующий **«Экспорт JSON · все данные»**. Импорт прогоняет checksum SHA-256 и независимую сверку значений/трасс; добавленные/удалённые связи входят в JSON и diff.
- В реестре формул исходные `baseline`, `perVyn`, `perLov` и другие поля из `data/character-balance-candidate.json` остаются неизменными. Новый optional `rules.ruleModifiers` хранит явные замены/удаления/новые проценты **только в памяти лаборатории и в JSON**; после F5 восстанавливается стандарт.
- Прежние правила базового калькулятора/ГЛР и фиксированные бонусы столиц сохраняют порядок. Проценты конструктора применяются **после плоских бонусов и прежних специальных правил, до caps**.

## Точная арифметика

Для показателя с базой B и набором источников:
1. Плоские бонусы добавляются: `B + Σ(points_i * flat_i)`.
2. Унаследованные бонусы столиц и глобальной регенерации остаются по прежнему порядку.
3. Все increased объединяются для данного показателя: `value *= (1 + Σ(points_i * increased_i) / 100)`.
4. Каждый more-источник применяется самостоятельно: `value *= Π(1 + points_i * more_i / 100)`.
5. Действуют прежние верхние caps; отрицательные модификаторы остаются **кандидатными**, игровые нижние границы/краевые случаи не утверждены.

**Пример** ВЫН=5 и исходно 150 ХП:
- изменить плоский бонус `+10` за ВЫН на `+12` → 160 ХП;
- добавить `increased +10%` за ВЫН → 160×1,5 = 240;
- добавить `more +5%` за ВЫН → 240×1,25 = **300 ХП**.
Это не рекомендация менять баланс игры, только пример проверки конструктора.

## Границы решения

- Доступны 24 известных выходных метрики. Изменять название метрики, создавать новую метрику №25, исправлять статус принятых решений или подключать к действующей игре этот конструктор **не умеет**.
- Для специальных городских коэффициентов `city.percent`, `regenFromMaxRpPercent`, контрольных очков `levelPoints` и капов оставлены отдельные числовые настройки; это не обычные источники flat/increased/more.
- Snapshot расширяет схему `rules` дополнительным optional полем `ruleModifiers`; новые значения безопасно читаются обновлённой Lab. Старые программы, не знающие модификаторов, могут отклонить новый snapshot и не должны молча игнорировать такие бонусы.
- Валидация расчёта не означает принятый боевой баланс. Статус UGD-0038 сохраняется `discussing`.

## Как проверить

1. Updater → 1 (обновить main) → 11 → Project Hub → Character Balance Lab, либо https://sunpole.github.io/uGame/character-lab/ после публикации Pages.
2. Развернуть «Редактор ВСЕХ коэффициентов», в «За 1 ВЫН» нажать **+ Добавить характеристику**, выбрать ХП → `increased` и значение, затем повторить с ХП → `more`. Существующая строка flat остаётся: всего три вида на одну характеристику.
3. Напротив АТК нажать **⋯ Изменить**, затем **Удалить**, увидеть уменьшение АТК на первом профиле. Можно выбрать в этом же окне другой показатель вместо АТК.
4. В шапке нажать **Экспорт JSON** и сохранить файл для обсуждения; затем **Вернуть стандарт**, импортировать файл, проверить восстановление формул.
5. F5 возвращает стандарты; игровые сохранения не затрагиваются. В окне редактора раздел «ЗРЛ» и отдельные городские проценты остаются обычными полями.

## Открыто

- Не утверждён боевой баланс, не утверждены новая отрицательная ОТВ, пассивы, ЗРП, тайминг и верхние границы. Достоверность расчётов и одобрение игровых решений — разные уровни.
- Старый клиент v0.2.57 до обновления может отклонить JSON с `ruleModifiers`; импортировать его необходимо в обновлённую лабораторию из main.
- При публикации отдельного игрового релиза потребуется версионировать формат и повторить браузерную QA с тегом и точкой отката.
