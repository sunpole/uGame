# Character Balance Lab · DEV (UGD-0038)

**Статус:** проектный калькулятор UGD-0038, discussing / needs-calculation; **НЕ принятый баланс, НЕ игровой CharacterSystem**.

Открыть через Project Hub → Инструменты → Character Balance Lab (отдельная вкладка) либо напрямую /character-lab/. Работает на localhost и GitHub Pages.

## Архитектура

- data/character-balance-candidate.json — источник **кандидатных** коэффициентов. Базы 100 ХП / 10 РП — демонстрационный пример владельца, не утверждённый игровой стандарт.
- src/character-balance/engine.js — независимое чистое расчётное ядро. Не импортирует GameState, SaveSystem, PlayerController, Phaser или StepSystem; не вызывает fetch и не сохраняет состояние. Возвращает значения, полный trace, бюджет и предупреждения.
- character-lab/index.html, lab.js, lab.css — сравнение **1–4 независимых профилей**. Исходные уровни 1/10/40/65; столица, 21 вариант старта, ВЫН/ЛОВ/ИНТ, ОТВ, ЖП>0/ЖП=0, все исходные базы и добавки будущих пассивов/предметов. Коэффициенты доступны в редакторе с живым пересчётом.
- tests/character-balance.test.mjs — числовые регрессии. tests/character-lab-browser-smoke.mjs — Chromium desktop/mobile.
- Навигация — только карточка в data/project-hub.json типа external, без изменений Phaser, GameState или сохранений.

## Формула-кандидат

1. Накапливаются baseline + ВЫН × perVyn + ЛОВ × perLov + ИНТ × perInt + ЗРЛ × perLevel + trunc(ОТВ/100) × perOtvBlock + city.flat + bonusesByDesire + externalFlat.
2. Проценты ёмкости РП применяются **после плоских бонусов**. Вдохновение +20% к максимальному РП.
3. Темп получает 1% максимального РП к РПС за секунду. Обычные +1% ХПС/РПС/ППС относятся к рассчитанным **скоростям**, а не к максимумам. ЛОВ даёт +0,01% к ХПС за единицу; аддитивные проценты одного типа складываются.
4. **100 ГЛР = +1% регенерации:** множитель 1 + ГЛР / 10000. Применяется к ХПС, РПС, ППС, ЖПС и РГШ. Не считать ГЛР как +ГЛР единиц/сек или +ГЛР%.
5. 100 УСТ/УВМ/ЗАЩ/УКЛ/ТОЧ/УСУ/КРШ = 1% соответствующего эффекта. СКА 100 = 1 атака/сек лишь по авторскому словарю, **базовая частота** ещё не определена. База РГШ = 5 для демонстрации текущей городской регенерации Шагов; окончательная связь с новой системой характеристик не принята.
6. В конце применяются предложенные автором **верхние капы**. Нижние границы, отрицательные эффекты и финальное округление игровых событий не приняты. В калькуляторе округление только для показа.
7. МКЯ копятся дробно; показывается число целых дополнительных ячеек floor(МКЯ).

## Исправления и ограничения

- Прежняя гипотеза **нулевого стартового итогового Покрова отменена владельцем** 10.10.2026. Уже на ЗРЛ 1 действует прямой бонус **+5 ПП**. Базовый вход ПП=0 не означает итог ПП=0 после сложения.
- ОТВ=1 на ЗРЛ 1–2, 600 с ЗРЛ 3 — **демонстрационный сценарий**, а не автоматическая выдача в gameplay. Каждые полные 100 ОТВ дают один комплект бонусов. Для отрицательного рейтинга временно принято округление к нулю с предупреждением — это не утверждённое игровое правило.
- Четыре фиксированных первых пассивных узла не имеют числовых формул. Их бонусы не выдуманы; для ручных экспериментов есть дополнительные плоские значения в каждом профиле.
- Не реализованы: начисление ЗРП, монстры/группы, штраф смерти, настоящее дерево пассивов, экипировка как источник действующих бонусов. Это отдельные будущие модули.
- Редактор хранит всё **только в памяти открытой вкладки**, без localStorage, SaveSystem, GameState, сетевого API и применения к игровому runtime. F5 сбрасывает ввод.

## Проверка

1. Выполнить node --test tests/character-balance.test.mjs.
2. Выполнить node tests/character-lab-browser-smoke.mjs после установки Playwright/Chromium, либо смотреть GitHub Actions.
3. Через Updater → 11 открыть Project Hub → Инструменты → Character Balance Lab. Сравнить ЗРЛ 1/10/40/65, изменить ОТВ 600→699→700, нажать РПС и увидеть все промежуточные слагаемые.
4. Изменить ЖП>0 на ЖП=0: наборы пассивов **заменяются**, не складываются.
5. В редакторе заменить +10 ХП/ВЫН на +20, увидеть пересчёт профилей, сбросить. Проверить desktop 1365×768 и mobile 390×844, горизонтальную прокрутку таблицы.
6. Отдельно убедиться, что игровые сохранения не изменены. **CI не заменяет ручной Windows QA.**
