# Character Balance Lab · реестр и безопасная админ-песочница (v0.2.57)

**Текущий статус:** эксперимент с кандидатными коэффициентами UGD-0038, НЕ действующая админка реального баланса. Включён только отдельно от игры на `/character-lab/` через Project Hub → Инструменты → Character Balance Lab.

## Возможности

- **Реестр:** 50 записей: **24** расчётных производных показателя, **5** базовых входов (ВЫН/ЛОВ/ИНТ/ЗРЛ/ОТВ), **4** столицы происхождения и **17** связанных правил/систем. Есть строка поиска, тип/статус, сокращение, полное название, единица, назначение, источники, порядок расчёта, источник в файле и точный статус. «Считается в Lab» НЕ означает «внедрено в живой Character».
- **Закреплённое сравнение:** кнопка 📌 возле любой из 24 строк результата, либо в карточке реестра. Sticky-панель остаётся сверху при прокрутке. Для 1–4 профилей показывает значения, выбор записывается в JSON. Панель может быть длинной, имеет свой ограниченный вертикальный скролл; на узких экранах — горизонтальный.
- **Редактор коэффициентов:** внутри существующей вкладки «Редактор ВСЕХ коэффициентов» — поиск по названию/группе, изменение исходных баз, perVyn/Lov/Int/Level/Otv, состояниям Желания, ограничениям и столицам. Меняется расчёт сразу, **не** игра.
- **Экспорт JSON:** кнопка выгружает snapshot с правилами, 1–4 профилями, закреплениями, выбранной формулой, **полной трассой всех 24 показателей по всем профилям**, предупреждениями, реестром, status=candidate-not-applied, исходным SHA-базисом и SHA-256. Такой файл можно прикрепить к следующему чату.
- **Импорт JSON:** схема, размер до 2,5 МБ, SHA-256, допустимые ID/профили, версия, модель и точные результаты проверяются до предварительного сравнения изменений. Для реестра требуется точное совпадение с доверенным текущим исходным; нельзя импортировать неизвестный или незаметно подменённый реестр. После проверки окно показывает diff коэффициентов, профилей и закреплений. **Применить в лаборатории** — только к памяти отдельной вкладки. F5 сбрасывает все правки до версий в GitHub.
- **Предупреждения:** неисследованная отрицательная Ответственность, предложенные капы, нулевое HP в крайних стартах без обязательных пассивов и разница между ШАГ Lab и фактическим StepSystem сохраняют честные статусы. Исходный авторский файл не редактирован.

## Что НЕ реализовано и специально не подменено

**Нет кнопки «применить к игровому балансу».** Нет записи в GameState, SaveSystem, localStorage, GitHub, сервер или объект Character, нет внедрения новых PvP/XP/пассивов. GitHub Pages статичен: для реального администрирования потребуются права, контроль целостности, PR, review, CI, релиз, миграции, rollback и серверное право применять утверждённую конфигурацию. JSON можно сохранить и предложить разработчику для отдельного PR, но это НЕ публикация.

## Пример процедуры

1. Updater → 1, затем 11 → Project Hub → Инструменты → Character Balance Lab.
2. Включить сравнение 2 либо 4 персонажей, выбрать ЗРЛ, столицу, ВЫН/ЛОВ/ИНТ и ОТВ.
3. 📌 закрепить ХП, ХПС, РП, РПС, УВМ или любые другие показатели, прокрутить вниз: шапка остаётся.
4. Найти «УВМ» в Реестре: **100 УВМ = 1%** сокращения КД; пример 10→9 секунд из строки 161 авторского файла ошибочен, на самом деле **10→9,9**. Принятые математические коэффициенты не изменены.
5. Найти «ВЫН» в редакторе, экспериментально увеличить `perVyn.hp` с 10 до 20. Проверить живой пересчёт закреплённых значений.
6. Экспортировать JSON и сохранить. Сбросить формулы, импортировать файл, увидеть diff, подтвердить применение **только в лаборатории**.
7. Перезагрузить F5: экспериментальные значения сброшены. Проверить, что игровое сохранение не изменилось.

## Валидатор доказательств (добавлен в main после QA-релиза v0.2.57)

Новая секция «Валидатор баланса · доказательства и пробелы» запускается отдельно кнопкой **«Проверить 5 460 сценариев»**. Она не изменяет состояние персонажа, сейвы, правила, реестр или GitHub.

Отчёт **отдельно** показывает:
1. **Технический расчёт** — типизированная схема, 50 записей реестра, 24 показателя текущих профилей, 21 стартовая комбинация × ЗРЛ 1–65 × ОТВ 1/600/699/700 = 5 460 сценариев; границы ОТВ, ГЛР, ранее согласованные ЛОВ/ВЫН и контрольные уровни. «✓» означает **только проверенное утверждение**, а не независимое доказательство полноты всей формулы.
2. **Статус правил** — берётся из реестра, со ссылками на источник: кандидат, принятый принцип или частично принято. Сам валидатор не повышает статус решения до `accepted`.
3. **Наличие в реальной игре** — derived показатели считаются исключительно в Lab; отдельные работающие StepSystem и ContainerSystem не считаются интеграцией расчётного CharacterSystem.

**Явно открытые механики** никогда не зелёные: новая шкала ОТВ и штрафы/высокий рейтинг, стартовые пассивы, опыт ЗРП/пати/монстры, связь со Шагами, время/Idle/воскресный цикл и настоящая интеграция CharacterSystem.

После изменения любого профиля или коэффициента результат прошлого прогона помечается **устаревшим**. Требуется нажать проверку снова. Отклонения экспериментальных коэффициентов от поздних решений по ЛОВ/ВЫН или стандартных milestone не называются математической ошибкой автоматически: показаны как требующие повторного согласования.

**Не путать:** зелёный GitHub CI проверяет код проверочных сценариев; зелёная браузерная валидация проверяет текущую конфигурацию по этим сценариям; ни то ни другое не проверяет баланс будущего PvP, снаряжения и ещё не реализованных правил.

Новые тесты: `tests/character-balance-validator.test.mjs` (в составе `npm test`) и дополнительные реальные desktop/mobile проверки внутри `tests/character-lab-admin-browser-smoke.mjs`. Результаты тестов проверять в CI конкретного PR. Ручной Windows QA — отдельно.


## Имена характеристик — русский + настоящий английский (2026-10-11)

**Публичные названия** для интерфейса/нового JSON теперь не используют латинскую транслитерацию русских сокращений. В панели профилей, сравнении и редакторе одновременно показываются русское обозначение и международный английский термин. Например:

- `ВЫН / CON — Constitution`, `ЛОВ / DEX — Dexterity`, `ИНТ / INT — Intelligence`: сокращения CON/DEX/INT официально представлены в Lineage II ([Aden patch notes](https://www.lineage2.com/en-us/news/aden-launch-patch-notes)); термины Dexterity и Intelligence также используются в PoE. Но **uGame не копирует игровые эффекты** этих RPG.
- `ОТВ / RESP — Responsibility`: **собственное имя uGame**, не общепринятая характеристика Lineage II/PoE/Albion. Английское `responsibility` выбрано буквально, чтобы не путать с resistance.
- Для 24 производных показателей определены полные английские идентификаторы: `health`, `healthRegeneration`, `resource`, `ward`, `attack`, `defense`, `evasion`, `accuracy`, `attackSpeed`, `cooldownReduction`, `globalRegeneration` и другие (полная карта — `src/character-balance/terminology.js`). Некоторые, например `Ward` для Покрова и `Desire` для Желания, **редакторские переводы uGame**, а не обещание одинаковой механики с чужими играми.

### JSON v2 и обратная совместимость

Кнопка «Экспорт JSON» записывает `schemaVersion: 2`, содержит `terminology` и **английские смысловые идентификаторы** во всех полях профилей, правил, зависимостей, метрик, реестра, пинов и расчётных трасс: `constitution`, `dexterity`, `intelligence`, `responsibility`, `perConstitution`, `perResponsibilityBlock`, `globalRegeneration` и т.д. Проверка SHA-256 сохранена.

При импорте v2 проверяется целостность, а затем данные переводятся в старый внутренний формат и **повторно пересчитываются**, чтобы не доверять чужим числам в JSON. **Старые v1 JSON из v0.2.57 читаются без миграции вручную.** Текущий игровой сейв не трогаем.

**Важное различие:** legacy ключи `vyn/lov/intel/otv` намеренно оставлены *внутри* существующего расчётного API, чтобы не сломать старые файлы и источники. Они **не выводятся как публичные идентификаторы нового JSON**; UI использует двуязычный словарь. Физическая замена технических ID во всех исходниках — отдельная миграция с риском совместимости, а не требование для корректной терминологии редактора. Старый релиз отката: [v0.2.57-pre-stat-names-20261011](https://github.com/sunpole/uGame/releases/tag/v0.2.57-pre-stat-names-20261011).
