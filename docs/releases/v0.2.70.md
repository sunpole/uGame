# uGame v0.2.70 — создание героя: 4 образа × 2 пола

**Статус на 11.10.2026:** код в ветке/PR. **Не считать релизом до загрузки восьми JPEG, успешных Node/Chromium desktop/mobile/Windows QA, merge и отдельной публикации GitHub prerelease.**

## Игровое решение и защита прогресса

- После успешного Pre-flight, **до** загрузки Phaser/автосохранений, появляется стартовый экран. Для нового браузера — создание героя; для существующего сейва — «Продолжить игру», «Создать нового героя» и, если уже есть архив, «Восстановить предыдущего героя».
- Имя (2–24 символа), четыре независимых **косметических** образа: латный воин, кожаный бретёр, служитель в ткани, смешанный образ воина духовного сана. Отдельно пол **мужской/женский**. Переключение мгновенно меняет URL/изображение; исходные изображения пользователя не изменяются по содержанию, лишь оптимизируются в JPEG.
- Всего восемь исходных PNG под своими настоящими именами `Изображение ChatGPT 11 окт. 2026 г., 22_45_51-1.png` … `22_45_58-8.png` в папке `assets/characters/`. Переименовывать и конвертировать вручную не нужно; веб-оптимизация — отдельный следующий этап после безопасной загрузки.
- В `GameState v1` добавлено только необязательное поле `player.heroIdentity={schemaVersion:1,name,gender,archetype}`. Старые сейвы получают `null`, не назначается выдуманный персонаж. Не меняются `classId`, `characterDraft`, `characterPools`, ОТВ, ЗРЛ/ЗРП, экономика, столицы, NPC и WorldGraph.
- При выборе **нового** вместо существующего нужен отдельный checkbox. Перед заменой `ugame.save.v1` выполняется полная резервная копия в `ugame.save.v1.hero-backup.<timestamp>`; если копия не создаётся, оригинал не заменяется. Повторное создание нового героя **не делается автоматически**.
- Реальный сервер аккаунтов/логин/пароль пока отсутствует. На локальном одно-браузерном прототипе хранить пароль бессмысленно и небезопасно; серверная авторизация, мультиплеер и мультислоты требуют отдельного проектирования. Архивы находятся в localStorage **того же браузера** — не облачные бэкапы.

## Проверки (фактические результаты отмечать после CI)

1. `npm test` — нормализация полей, 8 путей, старый SaveSystem v1, неизменность экономики и профиля, защита от утраты прежнего сохранения, резервное копирование.
2. **Настоящий Chromium desktop/mobile** — Pre-flight проверяет все 8 JPEG; затем создание и смена женского/мужского изображения, ввод имени, Phaser, Save/F5, выбор «Продолжить», WorldGraph 225 и обе лаборатории.
3. Windows PowerShell Updater и регрессия публикации текстур в GitHub Actions.
4. Отдельно ручной Windows QA владельца после публикации.

## Важный блокер — восемь портретов

Скрипт загрузки не смог разобрать русские пути из-за несовместимости кодировки PowerShell 5.1. Владелец загружает восемь исходных PNG без переименования через GitHub Web → ветка `feat/v0270-hero-creation` → `assets/characters/` → Add file → Upload files. Разработчик проверяет наличие, соответствие и Chromium QA до объединения.

## Проверка на Windows (после публикации)

Updater → `1 Update` → `11 Quick Run`. Новый браузер без save: пройти Pre-flight, выбрать образ, пару раз сменить пол — должен мгновенно появляться соответствующий портрет; ввести имя и создать, проверить его в шапке игры. Нажать F5: кнопка **«Продолжить игру»**, данные должны сохраниться. Для реального старого сейва: запускать без очистки браузера, выбрать **«Продолжить»**, проверить целостность класса, инвентаря, Шагов и позиции. Создавать нового вместо существующего **только на тестовом сохранении** — ожидается подтверждение и локальный архив.
