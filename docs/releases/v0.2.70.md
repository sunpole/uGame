## Уточнённый стартовый экран — четыре столицы

Владелец утвердил новую раскладку: после выбора **«Продолжить последнего» / «Создать нового»** (для существующего сохранения) либо сразу для первой игры видны **четыре вертикальные карточки одновременно** на десктопе, на узком мобильном экране — горизонтальная галерея без обрезки изображений. Общий переключатель М/Ж меняет **все четыре** портрета одновременно, а нажатие на карточку выбирает соответствующую столицу. Ниже имя и кнопка создания. Названия «Столица 1–4» временные. Порядок образов: латы / кожа / ткань / гибрид.

Точно по **UGD-0038, принятые решения №10 и №19**:

| Столица | Основной ресурс | Отличие ресурса | Стартовые преимущества |
| --- | --- | --- | --- |
| 1 | Сила | +1 РПС (плоский) | +10 СИЛ, +10 ЗАЩ, +1% ХПС |
| 2 | Концентрация | +50 к максимуму РП (плоский) | +10 КОН, +10 СКА, +1% РПС |
| 3 | Темп | +1% РПС от максимального РП за секунду | +10 ТЕМП, +10 УКЛ, +1% ППС |
| 4 | Вдохновение | +20% максимума РП | +5 ВДОХ, +10 ЖП, +1 ГЛР, +5 СКП |

Дополнительно под карточками видна утверждённая №10 схема **10 стартовых очков**: Столица 1 — +5 ВЫН и остальные 5 между ЛОВ/ИНТ; Столица 2 — +5 ЛОВ и 5 между ВЫН/ИНТ; Столица 3 — +5 ИНТ и 5 между ВЫН/ЛОВ; Столица 4 — +3 ВЫН, +3 ЛОВ, +3 ИНТ и одно случайное очко. Это *описание принятой схемы*, не запущенная генерация живого персонажа.

**Разделение статусов:** цифры **приняты в концепции**, но реальный Character Runtime ещё не применяет их автоматически. Выбранный `capitalId` (force/focus/tempo/inspire) записывается только в `player.heroIdentity`, без изменения уже существующего `characterDraft`, ресурсов, класса, стартовой локации или распределения 10 очков. Механическая интеграция после отдельного расчёта и тестирования. Никаких вымышленных названий городов не вводим.

## Игровое решение и защита прогресса

- После успешного Pre-flight, **до** загрузки Phaser/автосохранений, появляется стартовый экран. Для нового браузера — создание героя; для существующего сейва — «Продолжить игру», «Создать нового героя» и, если уже есть архив, «Восстановить предыдущего героя».
- Имя (2–24 символа), четыре независимых **косметических** образа: латный воин, кожаный бретёр, служитель в ткани, смешанный образ воина духовного сана. Отдельно пол **мужской/женский**. Переключение мгновенно меняет URL/изображение; используются исходные PNG пользователя без обрезки, конвертации и изменения содержимого.
- Всего восемь исходных PNG под своими настоящими именами `Изображение ChatGPT 11 окт. 2026 г., 22_45_51-1.png` … `22_45_58-8.png` в папке `assets/characters/`. Переименовывать и конвертировать вручную не нужно; веб-оптимизация — отдельный следующий этап после безопасной загрузки.
- В `GameState v1` добавлено только необязательное поле `player.heroIdentity={schemaVersion:1,name,gender,archetype}`. Старые сейвы получают `null`, не назначается выдуманный персонаж. Не меняются `classId`, `characterDraft`, `characterPools`, ОТВ, ЗРЛ/ЗРП, экономика, столицы, NPC и WorldGraph.
- При выборе **нового** вместо существующего нужен отдельный checkbox. Перед заменой `ugame.save.v1` выполняется полная резервная копия в `ugame.save.v1.hero-backup.<timestamp>`; если копия не создаётся, оригинал не заменяется. Повторное создание нового героя **не делается автоматически**.
- Реальный сервер аккаунтов/логин/пароль пока отсутствует. На локальном одно-браузерном прототипе хранить пароль бессмысленно и небезопасно; серверная авторизация, мультиплеер и мультислоты требуют отдельного проектирования. Архивы находятся в localStorage **того же браузера** — не облачные бэкапы.

## Итог код-ревью и дополнительных защит

- На старте большие PNG проверяются через **HEAD**, без загрузки 21 МБ в UTF-8 текст; фактическое изображение загружается только при показе/выборе портрета. Реальный Chromium дополнительно проверяет восемь HEAD-запросов, отсутствие фоновой массовой загрузки и декодирование PNG.
- Доступ к `localStorage` теперь в `try/catch`; при запрете приватностью доступна временная игра без сохранения, без повреждения прежних данных.
- [Код-ревью PR #76](https://github.com/sunpole/uGame/pull/76) выявило эти ситуации до выпуска.

## Загрузка восьми портретов — завершена

Владелец загрузил все восемь исходных PNG через GitHub Web. GitHub Directory API подтвердил присутствие и правильные имена каждого файла в `assets/characters/`. Избыточный ZIP удалён, изображения сохранены. Реальный Chromium открыл и декодировал все восемь изображений в desktop/mobile QA. Исходные картинки пока крупные (примерно 21 МБ суммарно); оптимизацию без потери качества можно делать отдельным патчем.
