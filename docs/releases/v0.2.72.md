# uGame v0.2.72 — компактный нижний HUD, каст и ЗРП

**Статус:** QA-кандидат до прохождения GitHub Actions, объединения PR, подтверждения GitHub prerelease и ручной проверки Windows.

## Запрос владельца (12.10.2026)

После успешного тестирования v0.2.71 перенести ресурсы из шапки вниз к семи скиллам. Владелец уточнил, что предпочтительны **два составных шара**, а не четыре отдельных: **ХП внутри + ПП внешним кольцом слева, РП внутри + ЖП внешним кольцом справа**. В центре оставить семь скиллов, над ними Stamina, ещё выше временной индикатор атак/кастов (0–100%). **Самая нижняя полоса перед футером** — текущие ЗРП/порог уровня и проценты накоплено/осталось; на уровне 65 отображать 0. Сохранения, баланс и навыки не менять.

## Реализация

- Перенесены **существующие** `#character-orb-hp` и `#character-orb-rp` с существующими кольцами ПП/ЖП, а не созданы дубликаты. Идентификаторы и CSS-переменные сохранены, значит общий CharacterVitalsHUD по-прежнему читает реальные сохранённые ХП/ПП/РП/ЖП.
- Создан `#combat-hud` в workspace: два составных шара обрамляют `#skill-hotbar`; Stamina осталась тем же `#header-stamina` + `#header-stamina-bar` с источником PlayerController, но теперь по центру над навыками.
- `src/action-meter.js`: прогресс реального времени, основанного на `performance.now()` и `requestAnimationFrame`, не на `setTimeout` или отдельном боевом таймере. Только **успешный** каст существующего «Импульса» запускает отображение фактической `RADIAL_IMPULSE.durationMs=300`; общее API принимает будущие длительности вроде 3000 мс, но трёхсекундный скилл пока не существует. Не появляется нового отката, блокировки движения, расхода ресурса или урона; частые касты просто перезапускают индикатор.
- `src/xp-meter.js` отображает текущий `player.characterProgress.zrl/zrp` без нового игрового состояния. На ЗРЛ 65 — визуальные ЗРП=0/0 и «MAX» (даже если старый DEV-сейв хранит ненулевой ЗРП; сейв не изменяем). Проценты считаются только при реально известном пороге.
- **Ограничение / не подделывать математику:** Project Journal UGD-0038 принял лишь **1 100 000 000 ЗРП на переходе 64→65**, а точная числовая таблица для 1→64 и алгоритм награды/уровней пока не финализированы. На ЗРЛ 1–63 показываем фактически накопленные ЗРП, «порог уточняется», **—% / —%** и пустую полоску, а на 64 — реальный % относительно 1,1 млрд. Никакого придуманного промежуточного опыта, автолевелапа или изменения DEV-кодов. Финальное отображение всех процентов требует **отдельного утверждения числовой XP-кривой**.
- Нижняя XP-строка — отдельная четвёртая строка CSS Grid `#app`, строго между workspace и footer, поэтому не закрывает DEV-консоль и игровые кнопки. Есть media CSS для mobile, 7 кликабельных слотов сохранены.

## QA-план и фактические результаты

- `npm test`: утверждённый 64→65 порог, неизвестность остальных, дробные/переполненные значения, MAX 65, примеры процентов, реальные интервалы 100 мс и 3 с в чистой функции, отсутствие таймеров/save у meter.
- **Настоящий Chromium desktop/mobile**: Pre-flight, Phaser, сохранения/F5, отношения орбов слева/справа от 7 скиллов, Stamina по центру, action выше Stamina, запуск индикатора только при успешном касте, XP строго между workspace/footer, отсутствие наложений, обе лаборатории.
- Windows PowerShell updater + texture publishing CI; проверка версии/файлов, прошлой точки отката.
- **Результаты вносить только после выполнения CI, не объявлять зелёными заранее.** Ручной Windows QA владельца — отдельная проверка.

## Проверка после релиза

Updater → `1 Update` → `11 Quick Run`. Убедиться в `v0.2.72`, открыть старого героя. Слева ХП/ПП, справа РП/ЖП, над 7 скиллами Stamina, над ней индикатор действия; нажать `1` с достаточным ресурсом — индикатор заполняется ~300 мс, никаких новых задержек у навыка. Нижняя строка XP всегда перед footer. На ЗРЛ 31 DEV показывает настоящие ЗРП и «порог уточняется», на ЗРЛ 64 — % от 1,1 млрд, на ЗРЛ 65 — MAX 0/0. F5 сохраняет прежние данные, расположение UI не зависит от сейва.
