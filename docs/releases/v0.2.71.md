# uGame v0.2.71 — стартовые характеристики героя и компактный экран

**Статус:** PR-кандидат; требуется Node + настоящий Chromium desktop/mobile + Windows Updater, затем merge, публикация prerelease и ручной QA на Windows. До завершения основной релиз — v0.2.70.

## Причина и исправление

Ручной QA автора 12.10.2026 выявил: при создании героя в v0.2.70 `player.characterDraft = null`. Поэтому `currentCharacterVitals()` показывал «ХП — / ПП — / РП — / ЖП —» и импульс просил сохранить профиль вручную, несмотря на выбранную столицу. На экране четырёх столиц нижняя кнопка «Создать героя» требовала прокрутки. М/Ж работает; секундное мигание пользователь согласился отложить.

- **Новый герой:** `src/hero-start-profile.js` связывает `heroIdentity.capitalId` с уже существующим `characterDraft = {schemaVersion:1,cityId,startIndex}`. Начальный набор определяется только существующими 21 допустимыми распределениями 10 очков (6/6/6/3) из `data/character-balance-candidate.json`. `CharacterVitalsHUD` использует тот же `currentCharacterVitals()`, что Character Balance Lab, и рассчитывает/сохраняет ХП, ПП, РП, ЖП без ручного выбора. Никаких новых числовых коэффициентов, РПС, бонусов, опыта или классов не введено.
- **Герой v0.2.70:** только при выборе «Продолжить» и наличии `heroIdentity` с отсутствующим `characterDraft` добавляется недостающий профиль. **Прежде чем менять сохранение — полная локальная резервная копия** `ugame.save.v1.hero-backup.<UTC timestamp>`. Сохраняются класс, позиция, ЗРЛ, ЗРП, ОТВ, инвентарь и экономика. После однократного назначения индекс сохраняется и не меняется при F5. При ошибке архивации/записи старая игра не заменяется.
- **Старые сейвы без идентичности** не мигрируют автоматически; ранее вручную сохранённый `characterDraft` любого города **не заменяется**. Для других персонажей сохраняется ручная возможность расчётной лаборатории.
- **Стартовый выбор:** криптографически случайный допустимый `startIndex` с unbiased rejection sampling, без общего статистического окна. **Ограничение:** принятая в Journal цель мягкого приоритета редких стартовых сочетаний за последние 1000 созданий в общем серверном масштабе ещё не реализована; без серверного учёта это честно не симулировать. Разделение между четырьмя столицами не изменено.
- **Композиция:** на небольших высотах desktop уменьшены изображения и вертикальные отступы; нижняя панель имени, подтверждения и «Создать героя и начать» закреплена у нижней границы содержимого. Мобильная горизонтальная галерея сохраняется. Мигание при М/Ж — отдельный будущий UX-патч.
- **Честный статус формул:** `data/character-balance-candidate.json` имеет `status: discussing`: вычисляемые в игре значения пока **прототипные**, не окончательно утверждённая экономическая/боёвая модель. Теперь эти существующие вычисления доступны новому игроку. Свободное распределение 3 очков при росте ЗРЛ 2–65 ещё не интегрировано; ранние примеры в Lab не объявлять финальной механикой.

## Проверки

- `npm test`: допустимые 10 очков, index 0…5/0…2, равномерный выбор без modulo bias, первичная инициализация 4 ресурсов и сохранение идентичности, безопасная миграция v0.2.70 с полной резервной копией, отсутствие повторной генерации после reload, отсутствие миграции старых сейвов и изменения уже сохранённого профиля.
- Chromium desktop 1365×768: **без прокрутки** видны кнопка создания и четыре столицы; после создания `#character-orb-hp` и `#character-orb-rp` заполнены; при F5 профиль остаётся; v0.2.70 без профиля безопасно мигрирует. Chromium mobile: та же инициализация, F5 и миграция, адаптивность.
- Pre-flight/Phaser, WorldGraph, обе лаборатории и Windows Updater — должны пройти обычные существующие regression workflows.

**Результаты тестов вписать после CI, не до.** Локальный ручной Windows QA автора ещё не проводился.

## Как проверить после релиза

1. `Update-uGame.cmd` → `1 Update`; затем `11 Quick Run` (после перезапуска). Проверить `v0.2.71`.
2. На ранее созданном в `v0.2.70` герое нажать **«Продолжить последнего героя»**. Не создавать нового ради проверки. После запуска проверить заполненные ХП/ПП/РП/ЖП и кнопку «Характеристики». ЗРЛ/ЗРП, инвентарь, класс, зона должны сохраниться.
3. Для нового героя открыть **отдельный профиль браузера**. После Pre-flight выбрать столицу/пол/имя: кнопка создания должна быть видна на экране ~1365×768 **без прокрутки**. Создать героя, проверить стартовые 10 очков соответствующей столицы и заполненные ресурсы, затем F5 → «Продолжить».
4. Если сохранение не устраивает, не чистить localStorage: есть резервная копия в той же области браузерного хранилища. Предыдущая точка отката для файлов: [v0.2.70](https://github.com/sunpole/uGame/releases/tag/v0.2.70) SHA `8594d967fc670343db389b656442a9ead89042fe`.
