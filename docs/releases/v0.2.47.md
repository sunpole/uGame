# uGame v0.2.47 — серверный фундамент общих экспедиций (локальный прототип)

Дата: 09.10.2026. Статус **server-authority QA**. Работает отдельный Node.js HTTP-сервис на `127.0.0.1`; **интеграция с Phaser, аккаунтами, публичным сервером и домашней/удалённой сетью ещё НЕ выполнена**.

## Что реализовано

- Серверная модель одной общей комнаты с конечным ресурсным stock и ограничением **12 отдельных участников**. Тринадцатый участник получает отказ, повторный claim не выдаёт дополнительные ресурсы.
- Добыча через общий сервер: автоматическая REAL TIME до истечения комнаты (10 секунд, 0.2 кг, 2 сервeрных тестовых Шага за цикл), ручная точность рассчитывается **по времени сервера**, а не по клиентской оценке точности. Одновременные автоциклы распределяются по единой временной очереди с последовательностью участников при равенстве timestamps.
- Рейтинг по фактически собранной массе после окончания комнаты. При полном истощении возвращается только часть **собственных серверных тестовых Шагов**: один участник — 25%; для нескольких участников #1 18%, #2 10%, #3 5%, #4–12 0%. Добровольный уход forfeits возврат, но сохраняет добытый серверный груз.
- **Ни один из этих процентов не утверждён как финальный баланс**; это безопасный тестовый фиксированный выбор внутри ранее обсуждённых диапазонов.
- Аутентификация dev-API: администратор создаёт комнаты по секрету минимум 24 символа; приглашение необходимо для входа; каждому участнику выдаётся отдельный секретный токен. В файле сохраняются только SHA-256 хэши токенов и кода приглашения.
- Локальный durable snapshot в `~/.ugame/expedition-authority.local.json` (Windows: домашняя папка пользователя, **не репозиторий и не GitHub Pages**). Атомарная запись и загрузка после перезапуска.
- HTTP API: `GET /health`; `POST /api/rooms` (admin bearer); `POST /api/rooms/:id/join` (invite); `GET /api/rooms/:id/status` (participant bearer); `POST /api/rooms/:id/actions` (bearer, действия `auto`, `pause`, `manual-start`, `manual-stop`, `leave`, `claim`).
- По умолчанию сервис недоступен извне и не запускается автоматически с игрой. Это ограничивает риски перед полноценным тестированием аккаунтов, авторизации и TLS.

## Как запускать локальный сервис

После Update и установки Node.js (никаких дополнительных npm зависимостей не требуется) в командной строке **на своём компьютере** задайте случайный секрет минимум 24 символа в переменной `UGAME_EXPEDITION_ADMIN_KEY`, затем выполните `npm run expedition:authority`.

Важно: **не отправляйте секрет или токены в чат и не публикуйте их в GitHub**. При правильном запуске появится адрес `http://127.0.0.1:5184`. Это отдельный разработческий сервер: обычный пункт Updater 11 по-прежнему запускает Phaser, но **не подключает его к комнатам**.

## Ограничения до настоящей MMO

- Phaser-экран экспедиции версии v0.2.46 всё ещё использует локальную добычу; он **не синхронизирован** с этим HTTP-сервисом. Два браузера сейчас не увидят друг друга в игровом интерфейсе.
- Тестовые 1000 серверных Шагов у каждого гостя не привязаны к реальному StepSystem персонажа и не выдаются в реальный рюкзак. До интеграции с аккаунтом нельзя смешивать эти два баланса.
- Нет настоящей регистрации пользователей, HTTPS, сетевого размещения, админки модерации, rate limit, серверной валидации профессий и экипировки, anti-multiaccount. Для публичной эксплуатации запрещено открывать этот сервер на внешний IP без отдельной архитектуры безопасности.
- Нет полной предметной экономики, долговременного аудита операций или HA/резервного копирования; snapshot — тестовый локальный.
- Физическая карта шахты по-прежнему реализована полноэкранной лёгкой сценой, без дополнительной зоны WorldGraph.
