# uGame v0.2.60 — Safe PC → GitHub South JPEG publishing

Status: QA candidate until merged main, Windows updater tests, desktop/mobile Chromium and release workflow pass.

## Why
The old updater supports only GitHub → PC (menu 1). Menu 10 imports six ignored local PNGs from Desktop; it does not push assets to GitHub. In contrast, South textures are **tracked JPEG files** and can be replaced locally, blocking Update 1's clean-check. The current GitHub JPG assets are small placeholders (south_256.jpg, city_south_512.jpg). Real user files live only on the Windows PC.

## New updater menu 12
**12 — Publish South JPEGs to GitHub (PR)**, or `Update-uGame.ps1 -Command publishtextures`.

- Allowlist only `assets/textures/biomes/south_256.jpg` and `assets/textures/biomes/city_south_512.jpg`.
- If present in this directory, prefer the full originals `ground_1024.jpg` → `south_256.jpg` and `city_ground_1024.jpg` → `city_south_512.jpg`; otherwise use matching destination JPG as source. The extension and bytes are unchanged; **no compression or resizing**. Target file names remain legacy for runtime compatibility, actual resolution may be 1024×1024.
- Show exact source/destination and measured dimensions; check JPEG header, dimensions, 1 KiB–20 MiB limits, no symlink. Require typing **UPLOAD**.
- Fetch current GitHub main into remote-tracking ref without touching local main. Create **disposable isolated Git worktree** from remote main, stage *only* allowed JPEGs, compare hash, commit and **push new branch** `assets/south-jpg-...`. No `git add -A`, no force-push and **never directly push to main**.
- If GitHub CLI is available/authenticated, create PR automatically. Otherwise print a direct GitHub compare link to create the PR; login for Git push may still be required.
- Return with the same local files, original local branch/HEAD and user changes. After reviewing and merging PR, use menu 1 Update to retrieve approved assets.

**Only committed and merged PR content reaches main/GitHub Pages**. A pushed branch alone does not fix the game. The uploader does not modify gameplay code, save data, texture defaults, image scale/opacity or gitignore rules. The new menu is specifically for South JPEGs, **not a general-purpose commit/push of arbitrary local files**.

## First use when local JPEGs are already modified

The existing (v0.2.58 / v0.2.59) updater does not contain menu 12 and rejects Update 1 if tracked JPEGs were replaced locally.

1. **Back up** your high-quality local JPEGs outside the repository first (for example to a folder on Desktop). Check backups open correctly. Never discard the only copy.
2. Check menu 2 `Status`; if the only tracked changes are `assets/textures/biomes/south_256.jpg` and `city_south_512.jpg`, restore these tracked paths from Git with `git restore -- assets/textures/biomes/south_256.jpg assets/textures/biomes/city_south_512.jpg` **only after independent backup**; do not restore unrelated edits.
3. Run menu 1 Update, restart the updater as requested.
4. Copy the original JPEGs back under **`ground_1024.jpg`** and **`city_ground_1024.jpg`** in `assets/textures/biomes/`. Do not rename originals or recompress; these names remain untracked and are used as source.
5. Run menu 12 → verify both dimensions and mappings → type UPLOAD. If `gh` isn't signed in, open the comparison link, create PR and merge after CI. Then run menu 1 again.

For any other local edits or unexpected Git status, stop and ask for help: do not use blind reset/clean.
